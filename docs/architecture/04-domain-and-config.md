# 04 — Domain state and configuration

[stack-stat-core](../../crates/stack-stat-core/Cargo.toml) separates data fetched from Git and GitHub from the view rendered in the terminal. The domain model describes stack order, the current worktree branch and its local-to-remote state, each layer's PR lifecycle, CI status, reviews, and local checks. Provider responses are mapped into the model by the compositor; the TUI reads the resulting state without depending on JSON response shapes.

## Composition

Successful Git, GitHub, and store snapshots are composed without I/O or clock reads. The normalized GitHub snapshot supplies stacked or single-mode rows and any PR identities; [provider normalization](05-providers-and-store.md#github-adapter) defines that mode and trunk selection. Git supplies the worktree's checked-out branch, its local-to-remote state, and current local SHAs. Composition applies that local sync state only to the checked-out branch's row and renders all other rows as in sync. The composed state also records which branch the GitHub snapshot was discovered for, because Git and GitHub poll independently and may briefly describe different branches. A PR number from discovery remains visible even if GitHub details are temporarily unavailable. A no-PR row retains local checks without PR-only data and is not a merge-ready PR. A PR that GitHub reports as closed without merging has a closed lifecycle: like merged and queued layers it has no readiness issues, is never `Go`, and is never the next PR to merge. A transport failure keeps the prior successful snapshot in the App, while an explicit not-in-stack result clears rows for a detached or empty HEAD or for the default branch without a PR.

For a local check, the current-SHA report wins; otherwise the newest older report is stale. Declared checks without a report render as missing, and a branch without a local ref never treats a stored result as fresh. Review requests without a submitted latest review become pending reviewer entries. CI skip patterns affect summaries, not underlying check visibility. Snapshot timestamps are carried through to the view so the TUI can show refresh age without reading the wall clock during rendering.

## Derived status

CI checks excluded by repository configuration remain visible in the PR detail view but do not count toward the row's passed/total summary. Failure takes precedence over running, which takes precedence over success; checks that completed as skipped or neutral are not counted in the total, so many conditional workflows do not make a finished PR look incomplete; skipped-only checks remain distinct. A workflow `STARTUP_FAILURE` and an unknown completed conclusion are treated as failures rather than falsely green. A non-merged layer needs a rebase only when GitHub's remote comparison shows its parent ref has commits absent from its head: the first non-merged layer compares against trunk, and every later non-merged layer compares against the nearest non-merged layer below it. A missing or failed comparison requires no rebase. The former blocks the verdict only when `rebase.onto_trunk` is set; the latter always blocks. A blocking rebase also marks every later unmerged layer (`RebaseNeed::Stacked`), because rebasing a layer rewrites the layers stacked on it. An unresolved-thread count is collected with each PR; it blocks the verdict only when the repository sets `reviews.gate_on_unresolved_threads`. Review summaries consider visible reviewers: changes requested outranks approval, which outranks an outstanding request. The bot toggle changes visibility without changing the original GitHub data. Missing local checks are configured expectations that were never reported; stale results refer to a previous branch commit.

See [ADR-0001](../adr/0001-remote-rebase-status.md) for why rebase status is remote-only and local drift is informational.

## Configuration sources

The repository's `.stack-stat.toml` at the worktree root owns check filters, expected local checks, bot names, and default bot visibility. Personal preferences live in `$XDG_CONFIG_HOME/stack-stat/config.toml`, the platform user configuration directory, or `~/.config/stack-stat/config.toml`. The user file may override polling intervals and the default review-column density. It cannot override repository check rules or bot names; ignored attempts produce a warning. Unknown keys and zero-second intervals fail configuration loading with a diagnostic naming the file or interval.

Glob patterns in the repository check filter match the whole check name: `*` matches a span and `?` matches one character. These display rules do not change what GitHub reports.
