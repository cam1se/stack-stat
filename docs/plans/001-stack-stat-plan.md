# stack-stat Implementation Plan

**Goal:** Bootstrap the `stack-stat` repository with the same AI/doc/CI conventions as `app-gp-logviewer`, then build the `stack-stat` Rust TUI and CLI described in [the design spec](../specs/001-stack-stat-design.md).

**Architecture:** A two-crate Cargo workspace. `stack-stat-core` is a library crate. It holds the domain model, config, a pure compositor, and three provider traits (`GitProvider`, `GitHubProvider`, `StatusStoreProvider`), each with a CLI/file-backed implementation and a fake. `stack-stat-tui` builds the `stack-stat` binary: a ratatui dashboard driven by tokio pollers through an mpsc channel, plus the `report`, `update`, and `version` subcommands. The app is generic over the providers, so end-to-end tests run the full app against fakes on `ratatui::backend::TestBackend`.

**Tech Stack:** Rust 2024 edition (stable toolchain via `rust-toolchain.toml`), ratatui + crossterm, tokio, clap, serde/serde_json/toml, chrono, anyhow, tracing, async-trait, percent-encoding, tempfile, self-replace, sha2/flate2/tar/zip/semver (self-update). External runtime prerequisites: `git`, `gh` (authenticated), and the `gh stack` extension. Repo tooling: GitHub Actions, release-please, Zensical (MkDocs-compatible) for the Pages site.

  - One crate: `cargo test -p <package>`; one test file: `cargo test -p <package> --test <file>`

- **Rustdoc.** Both crates' roots carry `#![deny(missing_docs)]`. Every public item gets a doc comment.

- `Config::load(repo_root: &Path, user_config_path: Option<&Path>) -> anyhow::Result<Config>` reads `<repo_root>/.stack-stat.toml` (optional) and the user file (optional), then merges them.
- `Config::user_config_path() -> Option<PathBuf>` resolves `~/.config/stack-stat/config.toml`. Use `$XDG_CONFIG_HOME` when set, and the platform config dir on Windows.

**Behavior:**
- Precedence: repo `[checks.*]` and `[reviews].bots` are authoritative. The user file can't add or remove skips, local checks, or bots. - Unknown keys are rejected (deny unknown fields) with a message naming the file and key. Poll values of 0 are rejected.
- Malformed TOML returns an error naming the file. The caller (startup) treats it as fatal.

**Files:**

  - `async fn poll_once(&mut self, source: Source)` — performs one provider fetch inline and applies it (tests use this instead of timers)

**Behavior:**
- Keys per the spec's keymap. Filter mode: printable chars append, Backspace deletes, Enter keeps the filter and returns to Normal, Esc clears and returns. Help mode: any key closes it; other keys are ignored while it's open. Confirm mode: `y` emits `Effect::Mutate`; any other key cancels with "cancelled" in the status line. `q`/Ctrl-C emit `Quit` in every mode except Filter, where `q` is text and Ctrl-C still quits.
- Mutations: `c` → `Checkout(selected)`, `p` → `PushStack`, `S` → `SyncStack`, and `m` → `ToggleDraft { number, make_ready: is_draft }` go through Confirm. `o` → `OpenPr` runs immediately. `R` → `Refresh(All)`. Keys needing a PR (`o`, `m`) on a row without a PR set "no PR for <branch>" and emit nothing. While a mutation is in flight, further mutation keys set "busy". A sync result shows its last non-empty output line in the status line; on failure, the error's first stderr line.
- Selection is kept by branch name across recomposes. If the branch disappears, select the nearest index. `g`/`G` jump to the first/last visible row. Navigation operates on filtered + sorted rows.
- Sort `s` cycles stack-order → PR-number ascending → status (worst `CheckSummary` first, ties in stack order). Bot toggle `b` flips `show_bots`. The reviews collapsed/expanded default comes from config `[display].reviews_default`; the detail pane always shows per-reviewer.
- Error retention: a failed GitHub fetch other than `NotInStack` keeps the last good GitHub snapshot and sets a status-line error (`⚠ fetch failed: …`, `⚠ rate limited, resumes in …`). - GitHub poll mapping: `stack_view` returning `Err(GitHubError::NotInStack)` becomes a successful `GitHubSnapshot { stack: StackOutcome::NotInStack, prs: [] }` (skip `pr_details`). Any other error is sent as `AppMessage::GitHub(Err(e))`.
- Pollers: git every `poll.git`s; store every `poll.store`s; GitHub every `poll.github`s, or `poll.github_active`s while `ci_active`. The app sets `ci_active` whenever any check is `InProgress`/`Queued` after a recompose. GitHub poll = `stack_view` then `pr_details(numbers in the stack)`; the snapshot is sent once both finish. On `RateLimited`, the next GitHub sleep is the reset hint if parseable, else 5 minutes. The store poller runs `gc` with the latest branch map published by the git poller through `tokio::sync::watch`, skips gc until the first git snapshot, then calls `read_all`. Every fetch sends `FetchStarted` first so the activity indicator can show.
- Runtime: enter raw mode + alternate screen; install a panic hook that restores the terminal; loop with `tokio::select!` over crossterm `EventStream`, the message receiver, and a 100ms tick interval. Render on tick and immediately after input. Effects are spawned on tasks that send their result back as `AppMessage::MutationDone`; the runtime then calls `refresh_all()`.
